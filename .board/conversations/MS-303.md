### agent · 2026-08-27T16:05:48.390Z

**MS-303 — "Move to next OOS from OOS page (just some < and > arrows)"**

One deliverable, small. The Order of Service editor is one page (`service-builder.html?date=YYYY-MM-DD`), and Services already treats Sundays as pure arithmetic — every week from July 2023 to two years out, document or not. So "next" is just +7 days. No query needed.

It reads **sharp, not trivial**. The title names the change exactly, but the page it lands on has two things that bite a naive build:

1. **It autosaves and guards the exit.** Three seconds after your last edit it writes, and there's a `beforeunload` handler that pops the browser's "Leave site?" box while you're dirty. Wire an arrow to a plain page navigation and you get that dialog on every click — during the guide-writing evening, which is exactly when someone clicks through eight Sundays in a row.
2. **The box lock follows you.** Only one person can sit in a hymn slot at a time, and presence is keyed to which page and which Sunday. Move dates without re-keying it and you appear parked on a Sunday you left, holding a box nobody can take.

There's also a real cost call: the page reloads the whole people directory and hymn index on open, so a full page nav per arrow is one line of code but slow, while swapping in place is snappier and more work.

**I'd take this to `/grill-with-docs`** — short, ~10 minutes. Four things to settle: does the arrow flush the pending save and go, does it reload the page or swap in place, where do the arrows stop, and does the URL change so back/refresh work. Everything else I can read out of the code.

**Placement:** the only open epics are "Roles & Serving Scheduler" and "Phase 1 (Legacy)" — neither fits. I'd call this standalone.

Sound right, or do you already know how you want the arrows to behave?

This page is a **live autosaving editor** with a `beforeunload` guard, and every prev/next arrow would be a full document navigation.

- Dirty tracking: `public\service-builder.js:626-628`

- Autosave debounce, **3 seconds**: `public\service-builder.js:1488-1503, 1573-1582`
  ```js

  ...
  scheduleSave() {
      if (!this.canEdit || this.saving) return;
      clearTimeout(this._saveTimer);
  ```

  The comment at `:1489-1493` says 3 s (rather than the elder documents' 1.5 s) because the save also settles involvement + fairness.
- **The navigation blocker:** `public\service-builder.js:727-732`
  ```js
  window.addEventListener('beforeunload', (e) => {
      if (this.canEdit && this.isDirty) {
          e.preventDefault();
  ```
